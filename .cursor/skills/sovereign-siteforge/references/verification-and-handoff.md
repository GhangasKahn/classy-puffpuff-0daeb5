# SOVEREIGN SITEFORGE — Verification & Handoff

## Zero-Trust Evidence Ledger

For every material claim record:

- Claim ID
- Exact claim
- Claim type (user-provided fact, retrieved fact, calculation, demonstrated capability, testimonial, case-study result, inference, aspirational statement, opinion, unknown)
- Source
- Source date
- Verification status
- Qualification required
- Page location

Rules: No unsupported numerical claims. No testimonial without attribution. No “best/leading/most/only” without evidence. No medical/legal/financial/safety/performance claim without support and qualification. No invented citations. If unverifiable, remove or rewrite honestly.

## Verification Ledgers

**Link ledger** — label, destination, internal/external, expected behavior, tested status (desktop + mobile + keyboard).

**Interaction ledger** — interaction, trigger, response, purpose, touch behavior, keyboard alternative, reduced-motion behavior, cleanup behavior, tested status.

**Asset ledger** — asset, source, rights, dimensions, loading behavior, alt treatment, responsive variants, tested status.

**Conversion ledger** — CTA, page location, destination, visitor intent, expected next step, truthful consequence, tested status.

**Responsive ledger** — for each important viewport (≈320, 375, 430, 768, 1024, 1280, 1440, 1920) confirm layout, typography, imagery, navigation, interaction, conversion, overflow, motion, accessibility.

## Adversarial Anti-Template Audit

Before completion ask internally:

- Could this hero/colors/section titles/animations belong to another company?
- Is the central metaphor visible throughout?
- Does each section have a distinct strategic job?
- Is any feature included only because it appeared in a source prompt?
- Are there three equal cards merely because three values were supplied?
- Is any “live” interface fictional?
- Is any copy generic?
- Is any visual trend unsupported by the brand?
- Does the site become ordinary when the logo is removed?
- Is the experience still understandable without animation?
- Is the primary action obvious?
- Is the brand memorable 24 hours later?
- Is the mobile version authored or merely compressed?

Revise until the experience has a defensible, brand-owned identity.

## Award-Readiness Evaluation

Weighted creative rubric: Design 40%, Usability 30%, Creativity 20%, Content 10%.

Also evaluate: semantics/SEO, animation/transitions, accessibility, web performance, responsive design, markup/metadata.

Internal 0–10 scorecard on: strategic fit, concept originality, art direction, typography, composition, imagery, motion, interaction, copy, proof and trust, conversion clarity, accessibility, mobile experience, performance, technical reliability.

If any critical dimension scores below 8, identify the cause, revise, and re-test. Do not manipulate the score.

A beautiful site with weak content, poor usability, inaccessible motion, or broken functionality is not award-ready.

## Implementation Sequence (Gates)

**Gate 0** — Project entry. Enter correct Sites project or new build. Preserve architecture. Gather only missing high-impact information.

**Gate 1** — Strategic synthesis (Brand Genome, visitor psychology, positioning, persuasion spine, proof inventory, objection map, CTA hierarchy).

**Gate 2** — Creative concept (governing concept, visual metaphor, emotional arc, layout genome, typography, color, imagery, motion grammar, signature interaction, anti-reference).

**Gate 3** — Content architecture (page count, section sequence, navigation, copy hierarchy, proof placement, objection placement, conversion moments, legal/trust content).

**Gate 4** — Design system (tokens, typography, grid, spacing, surfaces, controls, focus states, responsive behavior, motion primitives, reduced-motion).

**Gate 5** — Production implementation (complete pages, real content, real imagery, real interactions, real destinations, responsive layouts, metadata, accessibility, error/success states). No starter content, no TODOs, no lorem, no fake functionality.

**Gate 6** — Visual and interaction inspection of the actual rendered experience. Exercise primary navigation, CTAs, forms, signature interaction, mobile menu, keyboard, reduced motion, error/success states. Fix problems discovered in the rendered site.

**Gate 7** — Verification (claim, link, interaction, asset, accessibility, responsive, performance, privacy, anti-template, award-readiness scorecard).

**Gate 8** — Completion. Create final verified checkpoint. Do not report success until the final production state is verified.

## Completion Handoff

Return a concise handoff containing:

1. The completed website
2. The governing creative concept
3. The primary conversion strategy
4. The signature interaction
5. The proof used
6. The major accessibility and performance protections
7. Any genuine unresolved dependency
8. Any material assumption made because information was unavailable

Do not overwhelm the user with implementation internals unless requested.
