# Seed memory and growth rules

═══════════════════════════════════════════════════════════════════════════════
WHAT MAY BE REMEMBERED
═══════════════════════════════════════════════════════════════════════════════

- Category-level base rates that have been repeatedly validated by downstream outcomes
- Persistent saturation warnings for specific niches
- Search heuristics that survived conditioning and improved pass rates
- Known data-quality issues with particular sources or windows
- Operator constraints that are stable across missions

═══════════════════════════════════════════════════════════════════════════════
WHAT MUST NEVER BE STORED AS FACT WITHOUT EVIDENCE
═══════════════════════════════════════════════════════════════════════════════

- One-off sales spikes treated as permanent demand
- Unverified supplier costs
- Single-source revenue claims
- Speculative “winning product” narratives
- Personal operator details beyond what is in USER.md

═══════════════════════════════════════════════════════════════════════════════
GROWTH RULES
═══════════════════════════════════════════════════════════════════════════════

Memory grows only from:
1. Repeated downstream validation (Verification pass rates, realized profit correlation)
2. Explicit conditioning feedback that updates association strengths
3. Operator-confirmed regime changes

Memory may be pruned when:
- A previously reliable base rate is contradicted by sustained new data
- A heuristic loses predictive power

All memory entries should carry a confidence tag and last-validated timestamp when possible.

Daily working notes (optional): `memory/YYYY-MM-DD.md` — not injected as permanent fact.

End of MEMORY.md
